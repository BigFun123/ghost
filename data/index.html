About Ghost

Ghost brings servo control, motion sequences and a 3D robot view together in your browser.

Configure your robot, explore movements in offline simulation, and monitor live controller and sensor metrics.

Capabilities

  • 3D view — Explore your robot assembly, inspect components and watch commanded movements from different angles.
  • Servo mixer — Set servo positions, adjust motion modes and speed, and control individual outputs with mute and solo.
  • Sequencer — Build, save and play repeatable motion sequences, with looping and adjustable playback speed.
  • Metrics — Follow servo angles and simulated sensor readings over time, choosing which measurements to display.
  • Physics — Explore simulated gravity and collisions, drop test objects and inspect collision shapes in the 3D view.
  • Offline simulation — Configure your robot and try movements in the browser without sending commands to hardware.
  • Reinforcement Learning (coming soon) — Train robot behaviours through trial and feedback in simulation.

Sim to real

Build and explore your robot in simulation, then use the same robot configuration, servo mixer and motion sequences to control its physical counterpart through a connected Ghost controller.

Map the simulated servos to the controller's physical outputs so movements in the app drive the matching servos on your real robot. Offline simulation lets you try movements first; when connected to hardware, the controls send commands to the robot.

Simulation is a starting point: check servo directions, movement limits and clearances on the physical robot, since real loads and motion can differ.

Warning: powerful servos

High-torque servos, including models sold as “150 kg” servos, can cause serious crushing and pinching injuries. A small movement can apply substantial force through a horn or linkage.

  • Keep hands, hair, clothing and tools clear of moving joints. Secure the robot and keep other people outside its movement area.
  • Before fitting horns, adjusting linkages or working on wiring, disconnect servo power and support any parts that could fall when torque is removed.
  • For first tests, use small movements and low speeds. Check directions, limits and clearances before running a sequence.
  • Keep a physical servo-power disconnect within reach. Browser controls, mute, output-off commands and a network connection are not a safety-rated emergency stop.
  • Use the manufacturer's specified supply voltage, suitable wiring and protection. Follow the safety instructions for your servo and power supply.

Simulation cannot guarantee safe behaviour on hardware. Treat the robot as capable of unexpected movement whenever servo power is connected.

API endpoints

Paths are relative to the current host. GET reads data; POST changes settings or controls hardware. JSON bodies use Content-Type: application/json, except /api/servo, which uses application/x-www-form-urlencoded. Reboot needs no body. Examples below are request bodies. Servo command indices are 1-based; saved PCA9685 output channels are 0-based.

GET/api/devserverLocal server onlyIdentify the local development server and active robot.
POST/api/config/localLocal server onlyRequired configuration (full robot configuration object) and originalNames (previous component names in saved order; null when creating a new robot). Optional robot (folder name). Read /config.json first and preserve component settings. Writes files on the PC, not the device. Configuration must fit the controller’s 24576-byte limit.

Responses: read endpoints return JSON (except the plain-text log); command responses and errors are generally plain text. Check HTTP status before parsing: 400 invalid input, 409 configuration conflict or restart required, 413 request too large, 503 unavailable hardware or storage. Use the response text for the specific error.
